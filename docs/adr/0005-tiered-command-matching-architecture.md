# Tiered Command Matching and Context-Aware Intent Parsing Architecture

## Context
Voice commanding demands immediate response times for standard maneuvers (e.g., "take off", "land", "hold"), but simple pattern matching lacks the expressiveness to understand complex mission instructions or multi-step natural language intents. Furthermore, some spoken instructions represent **atomic primitive commands** (e.g., "move 10 meters forward") that must be rejected if the vehicle is disarmed on the ground, whereas others represent **high-level mission goals** (e.g., "start perimeter surveillance") that implicitly require preparatory steps (`ARM` -> `TAKEOFF` -> `START_SURVEILLANCE`) when issued while disarmed.

## Decision
1. **Single Abstract Parser Seam (`IntentParserInterface`)**: Decouple `VoiceCommandManager` from concrete parsing implementations via a single `IntentParserInterface` contract (`parse(const QString& transcript, const VehicleStateSnapshot& vehicleState)`), returning an `IntentParseResult` containing an ordered `QList<MissionIntent>` (`Command Sequence`). `VoiceCommandManager` holds and interacts with only one `IntentParserInterface` instance (mirroring `SpeechToTextInterface`) and remains agnostic to the internal parsing strategy.
2. **Pluggable Parsing Strategies (Phase 1 Baseline vs. Phase 2+ Regex-Free NLU)**:
   - **Phase 1 Baseline (`DeterministicMatcher`)**: Fast deterministic grammar/regex pattern matching (<10ms) implementing `IntentParserInterface` to validate the Phase 1 end-to-end pipeline and provide a lightweight test/baseline matcher.
   - **Phase 2 & Beyond (Regex-Free Local NLU Evaluation)**: Regex-based matching is **excluded** from Phase 2+ production tiers. Offline native C++ NLU backends implementing `IntentParserInterface` will be evaluated comparatively on a shared bilingual (Turkish/English) benchmark (see ADR-0013):
     1. **GLiNER2 / GLiNER2.5 (`onnxruntime` C++)**: Non-autoregressive bidirectional encoder unifying intent classification, slot/parameter extraction, and schema-guided JSON extraction with near-zero hallucination.
     2. **Seq2Seq → UAV DSL (`CTranslate2` C++)**: Encoder-decoder semantic parsing (`mT5`/`Flan-T5`, INT8) translating natural utterances into a closed, compact UAV DSL for multi-step composite commands and parameter-action binding.
     3. **Tool-Use / Extraction SLM (`llama.cpp` + GBNF C++)**: Small language models (`Qwen2.5-1.5B`, `xLAM-2-1B`, `NuExtract`) constrained by GBNF grammar for high-ceiling natural language, composite missions, and future planning/intent extraction.
     4. **Regex-Free Tiered Composition (`TieredIntentParser`)**: Optional cascade combining a fast, hallucination-free Tier 1 neural parser (e.g., `GLiNER2`) for atomic/parameterized commands and OOD rejection with a Tier 2 composite/planning parser (`Seq2Seq → DSL` or `Tool-Use SLM`) on low confidence or multi-step utterances—kept entirely behind `IntentParserInterface`.
3. **Neuro-Symbolic Separation — Context-Aware Goal Expansion (`GoalExpander`) vs. Atomic Pre-Conditions**:
   - **Shared Deterministic Symbolic Layer (`GoalExpander` / HTN)**: Rather than delegating multi-step vehicle-state planning to stochastic NLU models, all Phase 2+ parsers extract structured intents/goals and parameters (`altitude`, `distance`, `direction`, `speed`, `heading`, `targetVehicleId`, `targetArea`, `formation`) and delegate state-dependent expansion to a shared, 100% deterministic C++ `GoalExpander`.
   - **Atomic Commands** (`MOVE`, `CHANGE_ALTITUDE`, `CHANGE_HEADING`, `LAND`, `HOLD`, `RTL`) map 1-to-1 to a single `MissionIntent`. If issued in an invalid vehicle state (e.g., `MOVE` while disarmed), they are not auto-expanded; instead, they fail the execution engine's pre-condition check (`REQ-CORE-018`).
   - **Composite / High-Level Goal Intents** inspect `VehicleStateSnapshot` (`isArmed`, `isFlying`, `flightMode`) inside `GoalExpander` and expand into an explicit multi-step `Command Sequence` (e.g., `[ARM, TAKEOFF, <GOAL>]` if disarmed), presenting the full expanded sequence in the Operator Confirmation modal (`REQ-CORE-010`) before execution.

## Why
Keeping `VoiceCommandManager` coupled only to `IntentParserInterface` lets Phase 2 evaluate multiple native C++ NLU paradigms (non-autoregressive encoder, Seq2Seq DSL, grammar-constrained SLM, and regex-free tiered cascades) side by side without modifying the manager, confirmation modal, or command execution pipeline, while isolating vehicle-state expansion in a deterministic Neuro-Symbolic `GoalExpander` eliminates planning hallucinations.
